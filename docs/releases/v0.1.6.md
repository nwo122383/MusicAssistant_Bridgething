# Music Assistant BridgeThing 0.1.6

## Fixed

- Album covers no longer disappear into the music icon whenever the WebRTC connection recovers. Downloaded artwork survives reconnects to the same server and account.
- Browsing a large library no longer evicts a cover that is still displayed in Now Playing or another mounted view.
- Temporary artwork download failures get bounded retries without requiring another reconnect.
- WebRTC full player/queue polling runs every 15 seconds instead of every 4 seconds. Command responses have up to 30 seconds to arrive, reducing premature reconnects over Bluetooth-backed TURN connections. Live playback events still update the screen as received.
- Switching servers or accounts clears artwork, and a new track never reuses the previous track's cover while its own artwork loads.

## Store Preview

The catalog now includes a real 800 x 480 Car Thing Now Playing screenshot with album artwork. BridgeThing supplies the device frame around this image.

## Upgrade

Refresh the existing source in BridgeThing and install 0.1.6, or import `music-assistant-bridgething-v0.1.6.zip`. This is an app ZIP, not firmware. The app ID is unchanged and no credential re-entry is required for an ordinary update.

Requires BridgeThing firmware/libbridgething 0.17.1 or newer. Connection paths and phone sign-in are unchanged from [0.1.5](v0.1.5.md); setup instructions are in the [README](../../README.md).

## Verification

- All 71 automated tests passed.
- Tested on a connected Car Thing over Music Assistant WebRTC.
- During an app-only disconnect/reconnect test, the current cover stayed visible for all 105 checks and the app recovered automatically in about 26 seconds. Actual reconnect time depends on the phone, Bluetooth link, and server.
